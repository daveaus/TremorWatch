TremorWatch Code Review (2026-02-03)

Scope: Wear/phone sync, sensor handling, architecture/state, bug hunt, and data integrity. Review only; no code changes made.

**Critical Fixes**
1. Sensor-freeze recovery unregisters the wrong listener, leaving old listeners active and re-registering new ones. This can multiply callbacks, skew data, and drain battery. Fix by unregistering the actual listener (`monitoringEngine`). Location: `app/src/main/java/com/opensource/tremorwatch/service/TremorService.kt` (watchdog re-register block uses `sensorManager.unregisterListener(this)`).
2. No end-to-end acknowledgment or idempotency for batch transfers. The watch deletes local batch files after a channel write succeeds, but the phone does not confirm persistence; a crash on the phone can permanently lose data. Implement ACKs (the path exists but is unused) and delete only after ACK, or store batch IDs and dedupe. Locations: `app/src/main/java/WatchDataSender.kt`, `app/src/main/java/com/opensource/tremorwatch/service/TremorService.kt`, `phone/src/main/java/com/opensource/tremorwatch/phone/WatchDataListenerService.kt`, `shared/src/main/java/com/opensource/tremorwatch/shared/Constants.kt`.
3. Local medical data writes are non-atomic in several critical paths, so a process kill can corrupt data. Use `AtomicFile` or temp+rename with fsync for batch files, upload queue files, and calibration files. Locations: `app/src/main/java/com/opensource/tremorwatch/service/TremorService.kt` (watch batch files), `phone/src/main/java/com/opensource/tremorwatch/phone/WatchDataListenerService.kt` (upload_queue + calibration files), `phone/src/main/java/com/opensource/tremorwatch/phone/WatchDataListenerService.kt` (chunk_assemblies persistence).
4. Phone DB schema can silently accept duplicate samples when the watch retries. There is no batch ID or unique constraint, and `@Insert(REPLACE)` has no effect with auto-generated IDs. Add a `batchId` (or unique composite key like `timestamp+watchId`) and enforce dedupe. Locations: `phone/src/main/java/com/opensource/tremorwatch/phone/database/TremorSample.kt`, `phone/src/main/java/com/opensource/tremorwatch/phone/database/TremorDao.kt`.

**Performance Improvements**
1. Data Layer concurrency can saturate the channel and increase battery drain: `Channel.UNLIMITED` plus `PARALLEL_SEND_WORKERS=3` can queue large in-memory batches and open multiple channels concurrently. Prefer a bounded queue and a single worker, or dynamic backpressure based on failures. Locations: `app/src/main/java/WatchDataSender.kt`, `shared/src/main/java/com/opensource/tremorwatch/shared/Constants.kt`.
2. Accelerometer is registered at ~10 Hz, but FFT validation assumes 50 Hz. This can distort dual-sensor validation and waste CPU. Either register the accelerometer at the same rate as gyro or compute FFT using the actual accel sample rate. Locations: `app/src/main/java/com/opensource/tremorwatch/service/TremorService.kt`, `app/src/main/java/com/opensource/tremorwatch/engine/TremorMonitoringEngine.kt`, `app/src/main/java/com/opensource/tremorwatch/constants/MonitoringConstants.kt`.
3. Channel reads allocate based on an unchecked length prefix; a corrupted length can trigger large allocations or OOM. Add sanity caps (e.g., 1–5 MB) and reject oversized payloads. Location: `phone/src/main/java/com/opensource/tremorwatch/phone/WatchDataListenerService.kt` (`handleChannelBatch`, `handleCalibrationChannel`).
4. Stale chunk assemblies are never cleaned because cleanup runs only in `onCreate`. This can grow memory if chunks are lost. Trigger cleanup on each chunk receive or schedule a periodic task. Location: `phone/src/main/java/com/opensource/tremorwatch/phone/WatchDataListenerService.kt` (`startChunkCleanup`).
5. `PreferencesRepository` exposes synchronous `runBlocking` getters; if any are called on the main thread, they can block UI. Prefer `Flow`/`suspend` access and collect with lifecycle-aware scopes. Location: `app/src/main/java/com/opensource/tremorwatch/data/PreferencesRepository.kt`.

**Suggested Features**
1. Wire ViewModels into the UI and persist view state across configuration changes. Current `MainViewModel` classes exist but are not used in activities, and `remember` state will be lost on rotation/process death. Use `viewModel()` + `collectAsStateWithLifecycle` and `rememberSaveable` for transient UI. Locations: `app/src/main/java/MainActivity.kt`, `phone/src/main/java/com/opensource/tremorwatch/phone/MainActivity.kt`, `app/src/main/java/com/opensource/tremorwatch/MainViewModel.kt`, `phone/src/main/java/com/opensource/tremorwatch/phone/MainViewModel.kt`.
2. Add Wear OS ambient mode handling (AmbientModeSupport or AmbientLifecycleObserver) to reduce UI updates and battery usage while ambient, and present a simplified ambient UI. Location: `app/src/main/java/MainActivity.kt`.
3. Add explicit batch-level integrity checks (hash/checksum) and expose sync health metrics in the UI (last ACKed batch, pending count, retry rate). This provides patient-grade auditability for missed data windows.
4. Consider at-rest encryption for medical datasets (Room via SQLCipher or EncryptedFile for queued JSON) to protect sensitive health data if the device is compromised.
